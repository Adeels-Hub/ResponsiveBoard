AWS Scenarios — Fault Tolerance & Security

API Gateway with WAF → Lambda API Gateway with WAF → Lambda - API Gateway is regional, auto-scales, handles throttling & fault tolerance - WAF rules: rate limiting, GeoMatch, IP block - Good for internal APIs or direct client-to-API setups
CloudFront with WAF → API Gateway → Lambda CloudFront with WAF → API Gateway → Lambda - CloudFront adds global caching & edge protection - API Gateway is regional, throttles traffic, handles failover - WAF at CloudFront (only): rate limiting, GeoMatch, IP block - Best for public-facing websites or APIs accessed globally
API Gateway with WAF → ECS Fargate API Gateway with WAF → ECS Fargate - API Gateway is regional, auto-scales, throttles burst traffic - ECS Fargate tasks deployed across multiple AZs for HA - WAF protects API Gateway: rate limiting, IP block, SQLi detection - Ideal for serverless containers needing a lightweight gateway
CloudFront with WAF → API Gateway → ECS Fargate CloudFront with WAF → API Gateway → ECS Fargate - CloudFront caches responses and blocks bad actors early - API Gateway manages throttling & integrates securely with ECS backend - WAF at CloudFront for DoS, GeoMatch, rate limits - Good for high-throughput global APIs with container backends
ALB with WAF → ECS Fargate ALB with WAF → ECS Fargate - ALB is regional, supports path-based routing, auto-scaling targets - Fargate tasks in private subnets across AZs ensure fault tolerance - WAF on ALB: rate limiting, SQL injection, IP filtering - Best when you need L7 routing or WebSockets (which API Gateway lacks)
ALB with WAF → EKS ALB with WAF → EKS - ALB handles ingress to Kubernetes cluster pods across multiple AZs - WAF on ALB blocks abusive traffic, SQLi, IP-based attacks - EKS provides rolling updates, pod auto-healing, and fine-grained policies - Ideal for complex microservices architecture needing Kubernetes control
